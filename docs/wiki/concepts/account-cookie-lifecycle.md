# 概念: 账号与 Cookie 生命周期

## 核心目标

在尽量减少验证码调用的前提下，保证每个账号尽可能完成签到。

## 生命周期阶段

1. 装载阶段
   - 从环境变量或 Docker Cookie 文件读取 `NS_COOKIE`。
   - 从 `USER/PASS` 与 `USERn/PASSn` 读取账号密码。
   - 支持 `&` 与换行分隔，空槽位保留。
   - 末尾多余的分隔符会被丢弃：它不携带任何 Cookie 信息，
     若保留会凭空造出一个永远无法签到的账号，并让退出码恒为非 0。
2. 对齐阶段
   - 账号数组与 Cookie 数组按最大长度补齐，形成索引对应关系。
   - `cookie1&&cookie3` 表示第 2 个账号没有 Cookie，不会被压缩。
   - 账号顺序：`USER/PASS` 是第 1 个账号，`USER1/PASS1` 是第 2 个，依此类推；
     若未设置 `USER/PASS`，则 `USER1` 即为第 1 个账号。
   - 账号数与 Cookie 数不一致时打印告警，避免静默错位。
3. 执行阶段
   - 优先使用旧 Cookie 签到。
   - 只有返回 `invalid`（404 / 未登录 / 请先登录）时，才使用对应账号密码登录。
   - 网络错误、403、5xx 不会触发付费验证码。
4. 刷新阶段
   - 用新 Cookie 再次签到。
   - 成功后更新内存中的 Cookie 列表，并立即持久化一次。
5. 持久化阶段
   - 全部账号处理完毕后再次统一写回。
   - Docker：原子写入 `cookie/NS_COOKIE.txt`（0600）。
   - 青龙：通过 `QLAPI` 更新环境变量。
   - GitHub：默认关闭；开启 `GH_COOKIE_WRITEBACK=true` 后加密写入 Secret。
   - 其他环境：跳过保存。
   - Worker（KV）：按账号下标写入，读取时 KV 中已刷新的值优先于面板里的静态值。

## 关键收益

- 避免每次都触发登录与验证码。
- 多账号场景下减少互相影响，单账号失败不阻断其他账号。
- 空槽位与索引稳定，避免 Cookie 错配到其他账号。
- 环境无关的统一业务逻辑，环境差异只在持久化接口层处理。
